# 组提案：一组候选在考试题上比（玩具实验，已知最优解）

`loop.group` 的做法：提案器一次出一组候选，父版本和全部候选做同一批考试题（同一道题同一个种子），
考试题一半用来算组内优势、决定选谁，另一半交给准入确认。这个实验比较四种组内优势策略和"现在的循环"。

```bash
python benchmarks/group_toy/group_toy.py --budget 6000 --seeds $(seq 0 9)
python benchmarks/group_toy/group_toy.py --budget 6000 --seeds $(seq 0 9) --q 0.35 --collateral 0.7 --break-bias 0.8
```

## 设置

- 12 个"位置"，每个取 good / neutral / bad，权重不同（两个无关）。真实答对率起点 0.39，最优 0.85。
  标签只是名字：s1、s4、s7、s9 这四个位置 bad 反而最好，提案器要知道每个位置该选哪个（改对的概率 q）。
- 考试题 60 道（组提案时 30 道挑、30 道确认），练习题每代 30 道，每题做一次。
- agent 按真实答对率掷硬币，题目带 `rollout_seed` 时用它（公共随机数）。答错时说一个原因，一半概率指对。
- 提案器模拟 LLM：看一道错题的归因去改，改对的概率 q；还会顺手改动别处（collateral，其中 break_bias 是改坏）。
- 每组每个种子 6000 次 agent 调用，10 个种子。最终版本 = 最后一次接受的版本，按公式算真实答对率。

| 做法 | 说明 |
|---|---|
| A | 现在的循环：每代 1 个提案，考试分变高就收 |
| paired | 组提案（4 个）+ 减父版本的配对检验，Bonferroni 按组大小校正 |
| grpo | 组提案 + GRPO 式组内优势（减组内平均、除以标准差，组里含父版本） |
| best_of_n | 组提案 + 挑选择半上分数最高的 |
| training_free | 组提案 + 不选版本，把"比同组好 / 差的改法"写成经验进经验库，agent 照着做 |

组提案的四种，确认半上的准入都和 A 一样：分数变高就收。

## 结果（synthetic toy，非 benchmark）

"相对 A"是逐种子配对的差值，± 是标准误。

| 提案器 | 做法 | 最终真实答对率 | 相对 A | 平均接受次数 | 接受里真实变差 |
|---|---|---|---|---|---|
| 较好（q 0.6，collateral 0.5） | A | 0.788 ± 0.082 | — | 8.9 | 5.6% |
| | paired | 0.572 ± 0.084 | −0.216 ± 0.034 | 1.9 | 0% |
| | grpo | 0.773 ± 0.051 | −0.016 ± 0.035 | 8.0 | 0% |
| | best_of_n | 0.784 ± 0.048 | −0.004 ± 0.029 | 9.8 | 0% |
| | training_free | 0.764 ± 0.082 | −0.025 ± 0.046 | 5.8 | 0% |
| 较差（q 0.35，collateral 0.7，break 0.8） | A | 0.720 ± 0.089 | — | 7.8 | 7.7% |
| | paired | 0.406 ± 0.034 | −0.314 ± 0.035 | 0.2 | 0% |
| | grpo | 0.699 ± 0.044 | −0.021 ± 0.035 | 8.2 | 0% |
| | best_of_n | 0.701 ± 0.073 | −0.019 ± 0.033 | 9.8 | 0% |
| | training_free | 0.715 ± 0.043 | −0.005 ± 0.030 | 6.6 | 0% |

## 结论

1. **组提案（grpo、best_of_n、training_free）和现在的循环最终分数相当**（差 0.00～0.03，在 1 个标准误以内，不显著），
   但**收进的坏改动从 6%～8% 降到 0**。
2. **代价是成本**：每代考试题要做 5 遍（父版本 + 4 个候选），同样预算下走的代数更少。所以它换来的是"不收坏改动"，
   不是"更快变好"。
3. **parent_paired 太严**：30 道题上检验 4 个候选、按组大小校正后，几乎检不出几个百分点的提升，进步明显更慢。
   题目少时，用 best_of_n 或 grpo 挑、再交给确认半判，比在选择半上就要求显著更合适。
4. training_free 不改版本、只写经验，在这个玩具里效果和挑版本差不多。玩具里 agent 会完全照着经验做，
   真实 LLM 未必，这一点玩具测不出来。

这是玩具问题：效果大小、噪声、提案器和 agent 的行为都是设定的。

## 递归改进：把考试结果反馈给提案器

上面几种做法都只改进 agent，提案器（出改法的那一方）从头到尾一个水平，组内比较的结果用完就扔，本质上是爬山。
`loop.improver_feedback` 把每代"哪个改法在考试上好 / 差"写进提案器的策略说明（improver 可进化体），
提案器下次出改法时会读到。玩具提案器读到"BETTER … set sK=V"就偏向这个取值，读到"WORSE …"就避开。

```bash
python benchmarks/group_toy/group_toy.py --recursive --budget 6000 --seeds $(seq 0 9)
```

"读反馈带来的提升"是同场对比：每次提案器出改法的同一时刻，让一个不读反馈的同款提案器也出几份，
比较两者"出好改法"（真实效果为正）的比例之差。这样不受"越往后越难改好"的影响。

| 做法 | 最终真实答对率 | 相对 A | 接受里真实变差 | 读反馈带来的提升（前 1/3 → 后 1/3） |
|---|---|---|---|---|
| A：现在的循环 | 0.788 ± 0.082 | — | 5.6% | — |
| A + 反馈（只知道收没收） | 0.738 ± 0.101 | −0.051 ± 0.033 | 3.9% | +0.06 → +0.09 |
| 组提案（best_of_n） | 0.784 ± 0.048 | −0.004 ± 0.029 | 0% | — |
| 组提案 + 反馈（组内谁赢谁输） | 0.784 ± 0.086 | −0.005 ± 0.042 | 0% | **+0.13 → +0.11** |
| 组提案 + 打乱的反馈（对照） | 0.776 ± 0.054 | −0.012 ± 0.033 | 0% | +0.05 → +0.06 |

**结论**

1. **提案器确实变强了**：读组内比较反馈的提案器，出好改法的比例比同一时刻不读的高 11～13 个百分点；
   好坏标签打乱后只剩 5～6 个点，说明起作用的主要是反馈内容。
2. **组内比较是比"收没收"更好的教学信号**：同样是反馈，组提案模式的提升（+0.13）大约是普通模式（+0.06～+0.09）的 1.5～2 倍，
   因为一组里同时有"好的"和"差的"可以对比，普通模式只有一个结果。
3. **但还没有"越改越快"**：提升从前段到后段没有变大（+0.13 → +0.11），最终分数也没有超过不反馈的做法。
   玩具提案器只记最近 12 条、规则也简单，学到的东西很快饱和；而且这里的瓶颈是考试预算，提案器变强省下的不多。
4. 普通模式加反馈最终分数反而低一点（−0.05，不显著）：只凭"收没收"学，噪声大，学偏的时候会多出坏改法。

真正的"越改越快"需要提案器学到的东西能不断累积：经验要能总结、合并而不是只留最近几条，或者直接用组内的好坏对
去训练写改法的模型（DPO）。这两样玩具里还没有。
