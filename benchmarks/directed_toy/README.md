# 有方向的自我改进 vs 随机游走（已知最优解的玩具问题）

这个实验回答一个问题：给自我改进循环加上"方向"（组内比较、动量、统计检验），能不能比现在的循环更快、更稳地变好。
玩具问题的最优解已知，所以能直接算出每个版本的**真实**答对率，不用靠带噪声的考试分来猜。

```bash
python benchmarks/directed_toy/directed_toy.py --budget 6000 --seeds $(seq 0 19) \
    --q 0.35 --collateral 0.7 --break-bias 0.8
```

## 设置

- 被进化的是 12 个"位置"，每个取 good / neutral / bad，各位置权重不同（两个完全无关）。真实答对率起点 0.39，最优 0.85。
- 单个位置的效果只有 2～10 个百分点；考试题 30 道、练习题每代 30 道，每题做一次。噪声和效果同一个量级。
- agent 答错时报一个原因，只有一半概率指对。
- 提案器模拟 LLM：`q` 是"沿方向改对"的概率，`collateral` 是"顺手改动别处"的概率，`break_bias` 是顺手改动把东西改坏的概率。
- 每组每个种子 6000 次 agent 调用，20 个种子。最终版本 = 考试分最高的已接受版本，按公式算它的真实答对率。

| 组 | 做法 |
|---|---|
| A | 现在的循环：看一道错题的归因就改，考试分变高就收 |
| B | A + 考试题上的逐题配对检验（z ≥ 1.645） |
| C | 有方向（`loop.directed` 默认）：每组 3 个方向各 1 个修改，带"不改"对照在同一批练习题上比，最好的修改送去考试准入；动量决定下一组试哪些方向 |
| D | C + 每个方向 2 个修改（嵌套方差分析）+ 线搜索步长 |

A、C、D 的考试准入相同，差别只在候选怎么产生、怎么挑。

## 结果（synthetic toy，非 benchmark）

"相对 A"是 20 个种子上逐种子配对的差值，± 是标准误。

| 提案器 | 组 | 最终真实答对率 | 相对 A | 接受的改动里真实变差的比例 |
|---|---|---|---|---|
| 较好（q 0.6，collateral 0.5，break 0） | A | 0.730 ± 0.102 | — | 6.1% |
| | B | 0.457 ± 0.066 | −0.273 ± 0.028 | 0.0% |
| | C | 0.751 ± 0.055 | +0.021 ± 0.026 | 3.3% |
| | D | 0.717 ± 0.093 | −0.013 ± 0.028 | 5.0% |
| 一般（q 0.35，collateral 0.7，break 0.8） | A | 0.631 ± 0.074 | — | 8.9% |
| | B | 0.432 ± 0.053 | −0.199 ± 0.023 | 7.1% |
| | C | 0.652 ± 0.095 | +0.021 ± 0.029 | 4.8% |
| | D | 0.603 ± 0.090 | −0.028 ± 0.025 | 6.0% |
| 很差（q 0.2，collateral 0.9，break 0.9） | A | 0.581 ± 0.091 | — | 13.1% |
| | B | 0.413 ± 0.040 | −0.168 ± 0.019 | 10.0% |
| | C | 0.616 ± 0.097 | +0.035 ± 0.020 | 5.3% |
| | D | 0.552 ± 0.069 | −0.029 ± 0.027 | 11.0% |

## 结论

1. **考试题少时，严格的显著性准入（B）最差**：30 道题检不出几个百分点的提升，几乎什么都收不进来，三种设定下都比 A 低 0.17～0.27（z ≈ −9）。
2. **有方向（C）和现在的循环（A）持平，提案器越差优势越明显**（+0.021 → +0.035，最好的一档 z = 1.73，还不算显著），
   接受的坏改动大约少一半（13.1% → 5.3%）。
3. **D 的额外部件在这里不划算**：每个方向多写一个修改、再做线搜索，成本翻倍，换来的统计确定性没有变成更好的结果。
   所以 `loop.directed` 默认每个方向 1 个修改、不做线搜索；这两样保留为可选项。
4. 实现过程中试过、被实验否定的做法：只在"方向平均显著好"时才送修改去准入（提案器质量差时方向的平均效果被拖到 0，
   永远检不出来）；把 Bonferroni 摊到整个运行（门槛太高）；"连续几组没检出就算收敛"（把证据不足当成到头了）。
   现在的做法：方向只决定往哪里多试，收不收看单个修改；证据跨组累积；收敛要求"有把握没有方向能提升 δ 以上"。

这是玩具问题：效果大小、噪声、提案器的行为都是设定的。它说明了各部件在什么情况下有用，不代表真实 agent 上的数字。

## 方向识别测试：组内比较能不能找到正确的方向

[`direction_probe.py`](direction_probe.py) 不跑完整循环，直接用统计函数做几千次试验。每个方向的真实效果可以精确算出来，
所以能直接问：组内比较挑出来的方向，是不是真实效果最好的那个？对比"按归因次数挑"和"随机挑"。

```bash
python benchmarks/directed_toy/direction_probe.py --trials 400
```

**单组，3 个方向里挑最好的**（起点状态，每格 400 次；随机挑的命中率约 0.33）：

| 设置 | 组内比较命中（提案器较好 / 很差） | 归因次数命中（较好 / 很差） |
|---|---|---|
| 30 道题，每方向 1 个修改，独立随机（现在的默认） | 0.48 / 0.42 | 0.52 / 0.48 |
| 30 道题，每方向 3 个修改，公共随机数 | 0.65 / 0.71 | 0.50 / 0.53 |
| 120 道题，每方向 1 个修改，独立随机 | 0.51 / 0.53 | 0.63 / 0.63 |
| 120 道题，每方向 3 个修改，公共随机数 | 0.69 / 0.68 | 0.69 / 0.66 |

"公共随机数"= 对照和各个修改在同一道题上用同一个随机数（对 LLM 来说就是固定采样种子或温度 0），差别只来自修改本身。

**多组累积**（父版本不变，每组 3 个方向、30 道题、独立随机）：15 组以后，动量排序和真实排序的 Spearman 相关只有
0.17～0.29，归因次数排序是 0.85～0.87。按归因准确率扫描：归因完全不准（0）时组内比较 0.49、归因 0.31；
归因有一半准时，归因就反超。把两者按经验贝叶斯合并（归因当先验、测到的优势当观测）也没有超过只看归因。

**结论**

1. 按现在的默认设置（30 道题、每方向 1 个修改、独立随机），组内比较**基本找不到正确的方向**：命中率 0.42～0.48，
   只比随机好一点，不如数归因。单个修改本身好坏随机，再叠加答题噪声，一组测出来的优势信号太弱。
2. **公共随机数 + 每方向 3 个修改**能把命中率提到 0.65～0.77，在大多数设定下追平或超过归因。公共随机数还让
   "检出显著方向"的比例大幅提高（120 道题时 0.16 → 0.70），并压低"显著胜出者其实有害"的比例。
3. 没有公共随机数、提案器又差时，偶尔检出的"显著方向"有 30%～50% 其实是有害的：样本小时的显著多半是噪声。
4. 归因是更便宜、更强的方向信号（只要它有一定准确率）；组内比较的价值在于不依赖归因对不对，并且能挡住有害改动。
   所以候选方向应当先按归因排，组内比较用来确认和纠偏，而不是反过来。

## rubric 测试：多项 rubric、判别器噪声、rubric 有偏差

[`rubric_probe.py`](rubric_probe.py) 把玩具问题换成带 rubric 的版本：4 项（correct、tool_use、format，外加一个"代理项"
proxy，比如"回答够长"），每项由几个位置决定；真实目标是 correct 0.5、tool_use 0.3、format 0.2 的加权和，proxy 不值钱。
埋了一个陷阱：s11 改好会让 proxy 更容易过，但会伤害 correct。归因按"哪一项没过"在影响这一项的位置里追责。

```bash
python benchmarks/directed_toy/rubric_probe.py --trials 400
```

**1 多项 rubric**（无偏、判别器无噪声；3 个方向里挑对最好那个，随机约 0.33）

| 打分 | 30 道题、1 个修改、独立随机 | 30 道题、3 个修改、公共随机数 | 120 道题、3 个修改、公共随机数 |
|---|---|---|---|
| 整题对错 | 0.41 | 0.52 | 0.60 |
| rubric 加权分 | 0.56 | 0.70 | 0.76 |

按 rubric 加权打分，每道题给的信息多，组内比较的命中率整体高 0.10～0.18。归因按 rubric 项追责（0.47～0.60）
比按整题追责（0.44～0.57）略好。

**2 判别器噪声**（rubric 加权分，60 道题；ε 是每一项判反的概率）

| ε | 独立随机 + 1 个修改 | 公共随机数 + 3 个修改 |
|---|---|---|
| 0 | 0.57 | 0.71 |
| 0.1 | 0.51 | 0.65 |
| 0.2 | 0.44 | 0.55 |
| 0.3 | 0.42 | 0.52 |

判别器每一项错 20% 时，组内比较的优势基本被抵消。（玩具里的归因对判别器噪声不敏感，这是模型的简化：
被误判的"失败"仍按真实危害追责。真实系统里，追责一个误判的失败只会是噪声。）

**3 rubric 有偏差**（有偏 rubric：correct 0.3、tool_use 0.2、format 0.15、proxy 0.35）

- s11 的真实效果 −0.022，在有偏 rubric 上却是 +0.062。三个候选方向里有 s11 时，组内比较 60% 的时候选中它（无偏时 1%）。
- 连续改进 25 步（每步一组 + holdout 准入，同一个 rubric）：

| 准入 | 无偏 rubric：真实目标 | 有偏 rubric：真实目标 | 有偏时接受里真实变差 |
|---|---|---|---|
| 只有 holdout | 0.34 → 0.83 | 0.34 → 0.75 | 8.8% |
| + 人工标注集（20 道题按真实目标，不许显著变差） | 0.34 → 0.83 | 0.34 → 0.75 | 7.0% |
| + 分项不回退（核心 3 项任一 z ≤ −1 就拦） | 0.34 → 0.83 | 0.34 → 0.72 | 2.0% |
| + 分项不回退（z ≤ −1.645 才拦） | 0.34 → 0.83 | 0.34 → 0.74 | 7.0% |

**结论**

1. **rubric 越细，越容易找对方向**：多项加权打分比整题对错高 0.10～0.18。整题对错几乎只够分辨大的改动。
2. **判别器噪声会直接吃掉信号**：每一项错 20% 时，公共随机数和多个修改带来的提升基本没了。用 LLM 当判别器时，
   要先测它在同一份答案上给分的一致性。
3. **rubric 有偏差时，方法会稳定地朝"讨好 rubric"走**：单组 60% 选中有害方向；25 步后真实目标比无偏时少 0.08（约少 16% 的提升），
   而 rubric 分看起来一直在涨。统计做得越严，这个错方向找得越准。
4. **事后的检查拦不住这种小而稳定的偏差**：20 道题的人工标注集检不出每步 −0.02 的伤害；分项不回退只是在
   "拦坏改动"和"误拦好改动"之间换比例，门槛松时坏改动降到 2% 但总体进步更少，门槛紧时又拦不住。
   能根治的只有 rubric 本身：用人工标注集校准 rubric 各项的权重（判别器按 anchor 进化，`loop.judge_every`），
   而不是指望准入去补。
