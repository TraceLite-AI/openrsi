# 真实 LLM 上的 agent 自己出改法（loop.self_propose）

玩具实验（`benchmarks/group_toy --self`）里，递归有效的前提是写死的："agent 越强，它给自己出的改法越好"。
这里在真实 LLM（OpenAI 接口）上检验这个前提，并跑完整的 AnyRSI 循环。

任务：秘密运算符。8 个符号，每个代表一个未知的二元运算；系统提示里写了规则就照规则算，没写就按 a+b。
被进化的是系统提示。简单版运算是 a+b+1、max 这类；难版是 (a+1)·(b−1)、a>b 时 a−b 否则 a·b、(a·b) mod 10 这类，
要从错题里的几个例子推出公式。

```bash
export OPENAI_API_KEY=...
python benchmarks/self_propose_llm/probe.py --hard --model gpt-5.4-mini --levels 0 2 4 6 --samples 10
python benchmarks/self_propose_llm/loop_llm.py --model gpt-5.4-mini --seeds 0 1 2 --generations 8
```

原始结果在 `results/`（每个改法的原文、解析结果和真实效果）。

## 实验一：agent 变强后，它出的改法会不会变好？（probe.py）

造出强弱不同的 agent 版本：系统提示里写对 0、2、4、6 条规则。几个模型照规则计算都没问题，
写了 k 条规则的版本考试分就是 k/8 左右，所以这就是"agent 变强"。
对每个版本，用它做练习题、收集错题，生成和 `loop.self_propose` 完全一样的"改进你自己"题，交给三方回答。
三方是同一个模型、同样的采样种子，只有系统提示不同：

- **self**：当前版本自己（系统提示是当前版本的）
- **fixed**：起点版本（系统提示是起点的）
- **neutral**：普通助手

每个回答解析成补丁、应用，再到考试题上测分数变化。每格 10 次。

难版，改法的平均真实效果（考试分变化）：

| 模型 | 规则数 | self | fixed | neutral |
|---|---|---|---|---|
| gpt-6.1-terra | 0 / 2 / 4 / 6 | +0.25 / +0.13 / +0.18 / +0.25 | +0.25 / +0.13 / +0.18 / +0.24 | +0.25 / +0.13 / +0.16 / +0.24 |
| gpt-6.1-sol | 0 / 2 / 4 / 6 | +0.25 / +0.14 / +0.19 / +0.25 | +0.25 / +0.13 / +0.19 / +0.25 | +0.24 / +0.15 / +0.19 / +0.25 |
| gpt-4o-mini | 0 / 2 / 4 / 6 | 0.00 / −0.06 / 0.00 / −0.03 | 0.00 / −0.06 / 0.00 / −0.05 | +0.03 / −0.04 / +0.01 / −0.04 |

- gpt-6.1 两个模型的改法 100% 能解析、100% 有用：错题里出现了哪几个符号，就把那几个符号的公式全推对。
  上限由错题里有几个符号决定，不由出改法的水平决定。简单版同样如此。
- gpt-4o-mini 推不出公式，改法基本没用或有害。
- gpt-5-nano 多数回答为空（推理把 4000 token 的输出额度用完），不计入。

## 实验二：完整循环（loop_llm.py）

难版，同一个模型做题、出改法，3 个种子 × 8 代：

| 模型 | agent 自己出改法（self_propose） | 独立的提示改写器（PromptRewriter） |
|---|---|---|
| gpt-6.1-terra | 0.04 → **0.90**（0.92 / 0.83 / 0.96） | 0.04 → **0.93**（0.96 / 0.88 / 0.96） |
| gpt-6.1-sol | 0.04 → **0.88**（0.92 / 0.75 / 0.96） | 0.04 → **0.89**（0.96 / 0.75 / 0.96） |
| gpt-4o-mini | 0.04 → 0.06（24 个改法收了 1 个） | 0.04 → 0.04（24 个改法收了 1 个） |

`loop.self_propose` 在真实模型上能直接用：agent 回的 JSON 补丁都能解析，循环正常推进。和独立改写器效果相当。

## 结论

1. **同一个模型，只改提示，递归不发生。** 在四个规则数、三个模型上，"当前版本自己出改法"和"起点版本出"
   "普通助手出"效果一样。agent 变强是因为提示里多了规则，而这些规则对"写改法"没有帮助。
   出改法的三方都能看到当前提示的内容，所以"多知道的东西"也不是 self 独有的。
2. **出改法的水平主要由模型本身决定。** gpt-6.1 的改法几乎全对，gpt-4o-mini 的几乎全没用，完整循环里也是一个到 0.9、一个停在 0.05。
   所以"agent 越强、改法越好"在**模型层面**成立。要让递归真正发生，被进化的得是模型权重这类"通用能力"，
   而不只是任务知识。
3. 这个任务的瓶颈是信息（错题里出现了几个符号），不是出改法的水平，所以强模型之间看不出差别。
   提示里如果写的是"通用的做事方法"而不是"具体规则"，结果可能不同，这里没有测。

## 实验三：弱模型能不能像梯度一样找到方向？（拆小合并，`loop.group.atomize` + `merge`）

弱模型（gpt-4o-mini）一次只出一个改法时，它的改法对错混在一起，整个收或整个扔。拆小合并：
每代出 4 个改法（`anyrsi_llm:PatchProposer`，普通助手身份），拆成一条条小改动，每条单独加到父版本上，
在考试题上和父版本逐题相减（有限差分），所有变好的合并成一步。玩具实验里这让弱提案器从 0.61 提到 0.81
（见 [group_toy](../group_toy/README.md#像梯度一样找方向拆成小改动逐条测变好的合并成一步)）。

各组的成本对齐到约 2000 次 agent 调用，3 个种子。最终版本用 48 道没用过的新题打分（考试题被拿来挑过，会偏高）：

| gpt-4o-mini，新题分数 | 简单版（种子 0 / 1 / 2） | 难版 |
|---|---|---|
| A：普通循环（64 代） | 0.47（0.56 / 0.38 / 0.48） | **0.13** |
| 挑最好一个（16 代，考试题分两半） | 0.42 | 0.15（2 个种子） |
| 挑最好一个（16 代，不分） | 0.45 | — |
| 拆小合并（16 代，考试题分两半） | 0.33 | 0.06 |
| **拆小合并（16 代，不分）** | **0.58（0.62 / 0.50 / 0.60）** | 0.08 |

拆小合并（不分）相对普通循环，逐种子配对：简单版 **+0.10 ± 0.02**（三个种子都更高），难版 −0.05 ± 0.03。

**结论**

1. **弱模型偶尔能提对时，测量能把方向找出来。** 简单版上 gpt-4o-mini 一次出的改法大多不对，拆开逐条测、合并变好的，
   比普通循环高 0.10，比"挑最好一个"高 0.13。
2. **考试题不能分两半。** 一条规则只影响含那个符号的题（24 道里 3 道），分两半后某一半里常常只剩 0～1 道，
   在选择半上测出来的好方向到确认半就看不出来了，被拒掉。这次的改动都是"局部"的（只影响一部分题），这时要么不分，
   要么把考试题加多。玩具里每个改动影响所有题，所以分两半没问题。
3. **模型几乎提不出对的方向时，测量也救不了。** 难版上 gpt-4o-mini 提了 246 条规则只有 2 条对（不到 1%），
   拆小合并反而比普通循环差：普通循环 64 代看了 64 批不同的错题、出了 64 次改法，"多试"比"测得细"更有用。
4. 同一个种子下，同一道题做两次结果完全一样（temperature 1 和 0 都是），测量噪声不是问题。
